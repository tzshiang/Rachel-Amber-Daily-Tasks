# 下次開新 App，怎麼跟 Claude Code 講需求

把「安安樂樂打卡 App」這次實際講過的需求拆解成欄位，整理成一份可以直接複製填空的規格模板 ——
每個欄位都附上這次的真實範例，最後再附上「早知道一開始就講」的清單。

同系列文件：[案例學習手冊](./dev-guide.md) · [開發 SOP](./dev-sop.md)

## 新 App 需求模板：8 個欄位

### 01 · 一句話介紹

做什麼、給誰用，一句話講完。

- **模板：** 我想要開發一個讓＿＿使用的＿＿應用程式。
- **這次的範例：** 我想要開發一個讓我女兒安安和樂樂每日任務打卡的應用程式。

### 02 · 使用者與身分

列出所有會用這個 App 的人，以及每種身分能看到/操作的範圍有什麼不同。

- **模板：** 使用者有：＿＿。其中＿＿身分可以看到／操作＿＿，跟其他人不一樣。
- **這次的範例：** 安安、樂樂各自用自己的打卡頁面；爸爸媽媽可以從後台看到他們每日完成的進度。

### 03 · 核心功能清單

逐條列出具體功能，不要只講方向。清單式列出比一句話描述更精準。

- **模板：** 核心功能：＿＿、＿＿、＿＿⋯
- **這次的範例：** 每日任務：彈鋼琴、讀一本書、寫一篇日記、完成作業、一段今天想分享的事情、洗澡。

### 04 · 視覺與品牌風格

目標受眾的風格、每個身分要不要不同主題色、語言（單語/雙語）。

- **模板：** 風格是＿＿。＿＿喜歡＿＿色，＿＿喜歡＿＿色，各自使用時依風格呈現。
- **這次的範例：** 七歲小女孩喜歡的風格；安安喜歡粉紅色、樂樂喜歡紫色，各自使用時依風格呈現；任務名稱中英對照。

### 05 · 資料規則 ★ 最容易漏掉

這次最容易漏掉的一項，務必想清楚再開口。

- **模板：** 資料需不需要跨裝置同步？（單機儲存 / 雲端資料庫）需不需要密碼保護？
- **這次的範例：** 一開始沒講，等 App 做完部署測試後才追加「需要保留在雲端 DB」——多花了一輪工把 localStorage 改成 Supabase。

### 06 · 統計與遊戲化機制

如果要有進度追蹤、排行、獎勵機制，講清楚統計週期跟獎勵規則的彈性程度。

- **模板：** 統計週期：＿＿。完成率對應的獎勵：＿＿（可以讓 Claude Code 自行設計分級）。
- **這次的範例：** 統計每一週和每一個月的完成狀況，依完成率給予不同的愛心獎勵（分級規則由 Claude Code 設計）。

### 07 · 平台與裝置需求 ★ 也常漏掉

這次也是部署完才問到，建議一開始就講清楚要支援哪些裝置。

- **模板：** 主要用＿＿裝置，但也需要在＿＿（手機／平板／桌機瀏覽器）正常使用。
- **這次的範例：** 沒有事先講，App 上線後才問「iPad、電腦瀏覽器可以正常運作嗎」——還好原本就是響應式設計，沒有大改，但排版沒有特別針對大螢幕優化。

### 08 · 這次先不做 / 之後再說

明講範圍界線，避免 Claude Code 自己猜測做出不需要的東西，或是漏掉真正要的。

- **模板：** 這次不需要＿＿；＿＿之後有需要再說。
- **這次的範例：**（這次沒講，Claude Code 自行決定不做登入系統、後台用簡單 4 碼 PIN 取代——這次猜對了，但講清楚會更保險。）

## 這次「事後才補」的需求，付出了什麼代價

| 漏掉的需求 | 什麼時候才補上 | 代價 |
|---|---|---|
| 資料要跨裝置同步 | 部署上線、實測後才提出 | 整個資料層從 localStorage 改架構成 Supabase，多一輪開發跟部署設定 |
| 要支援平板／桌面瀏覽器 | 部署上線後才問 | 額外一輪測試確認（好在本來就是響應式設計，沒有傷筋動骨） |
| GitHub repo 要有初始內容 | 要開 PR 時才發現 repo 是空的 | 臨時補建空的 `main` 分支才能開 PR |

這三項有共通點：**都是「開發過程中才發現需要決定」的架構性問題**，而不是功能細節。架構性問題早講，代價是多花一分鐘想清楚；晚講，代價是整層打掉重練。

## 追加功能時，怎麼講最精準

App 做完之後陸續追加的小功能，跟一開始的完整規格不同，不需要走完 8 個欄位，但一樣要「條列具體規則」，不要只講方向。這次「九九乘法表練習」的請求是一個很好的示範：

> 在這個程式上，再增加一個功能 99 乘法表考試練習：
> 1. 可以選擇每個數字(2-9)的 99 乘法表練習
> 2. 也可以選擇亂數(2×3，4×2，8×3⋯⋯)出現 20 題的練習

**這個請求好在哪：** 講清楚了功能名稱、兩種明確的模式、每種模式的具體規則（數字範圍 2-9、亂數題數 20 題），Claude Code 不需要用猜的就能一次做對。

## 把 8 個欄位串成一段開場白

實際跟 Claude Code 對話時，不用逐條填表，用自然語言講一段話就好——下面是把這次的請求，補上第 5、7 兩個當時漏掉的欄位後，會長的樣子（**粗體**處是原本沒講、建議這次補上的部分）：

> 我想要開發一個讓我女兒安安和樂樂每日任務打卡的應用程式。
>
> 每日任務會有：彈鋼琴、讀一本書、寫一篇日記、完成作業、一段今天想分享的事情、洗澡。任務可以幫我轉換成英文。
>
> 版面的風格是七歲小女孩喜歡的，他們是雙胞胎，安安喜歡粉紅色，樂樂喜歡紫色，所以他們各自使用時可以依據他們的風格。
>
> 然後可以統計每一週和每一個月的完成狀況，給予不同的愛心獎勵。
>
> 爸爸媽媽可以從後台看到他們每日完成的進度。
>
> **資料需要能跨裝置同步——安安樂樂可能用平板打卡，我自己用手機看後台，所以要用雲端資料庫，不要只存在單一裝置的瀏覽器裡。**
>
> **這個 App 主要在手機上用，但也希望在 iPad 和電腦瀏覽器上能正常顯示，不用一定要撐滿大螢幕，但排版不能跑掉。**

這樣一次講清楚，可以省掉這次「上線後才發現要改架構」的那一輪來回。
